What this container does

Loads any Geotab Add-In in an iframe, proxies all api.call() requests through the postMessage bridge, and gives you real-time visibility and control over every Geotab API call.

How the bridge works

  • CORS available: fetches the HTML, scans for risky patterns, injects geotab-bridge.js, loads via srcdoc. Bridge activates automatically.
  • No CORS: loads the URL directly. Bridge activates only if the Add-In already includes geotab-bridge.js.

Security checks on every call

  • Origin validated against iframe's contentWindow
  • Sliding-window rate limit (20 calls/s)
  • TypeName and Method block lists applied instantly

What a server-side proxy adds

A proxy closes all the "cannot do" gaps: it sees the raw HTTP traffic, can cache responses, enforce per-user quotas, log to a database, redact sensitive fields, and bridge to non-Geotab APIs without exposing credentials to the browser.

Option A — add the bridge script to your Add-In's HTML:

<script src="https://fhoffa.github.io/geotab-vibe-guide/examples/addins/geotab-bridge.js"></script>

Option B — serve with CORS headers so this container can inject it automatically:

nginx:   add_header Access-Control-Allow-Origin *;
Apache:  Header set Access-Control-Allow-Origin "*"
Express: app.use(require('cors')())
