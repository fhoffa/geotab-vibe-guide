# Evidence log — reusable probes + an append-only results ledger

Every empirical claim in this skill is **observed, point-in-time, and re-measurable**. The Geotab data
agent, MotherDuck, and a given fleet all change, so this file is built to **accumulate runs over time, not
be overwritten.**

**How to use / how to add next week's run:**
1. Re-run the **probes** in §1 (stable prompts/SQL — they rarely change).
2. **Append a row** to the §2 ledger for each probe: `date · DB · probe · result · reference · notes`.
   Don't edit old rows — add new ones, so drift is visible over time.
3. If you want the full verbatim prompt+answer+SQL for a run, drop a dated block in §3 (Run archives).
4. If a number changed enough to matter, update the dated figure in the prose docs **and** cite the new
   ledger row. (Claims in SKILL/refs point here; the *latest* ledger row is current truth.)

> **Provenance of older rows.** Rows dated **before 2026-10-29** were measured through Geotab's earlier
> natural-language bulk channel (`GetAceResults`, same engine family as today's data agent). They stay here
> because they describe Geotab pipeline behavior and MotherDuck-side validations that don't depend on the
> tool; Geotab-side agent behavior was re-measured on the data agent from 2026-10-29 (probes P19–P27). How
> the two differ: [`../CHANGES_v1.1_to_v2.0.md`](../CHANGES_v1.1_to_v2.0.md).
>
> Tool legend: **Data agent** = `mcp__MyGeotab_MCP__AskDataAgent`; **Get API** = `Get` / `GetCountOf` /
> `Add` / `Remove`; **MotherDuck** = `mcp__MotherDuck__query` / `query_rw`. Databases: Geotab `demo_fh4`,
> `Demo_fh_vegas4`, `demo_fh8`, `demo_fh_vegas8`; MotherDuck mirrors `geotab_demo_fh4`, `geotab_Demo_fh_vegas4`
> (`my_db` = the early name of the first mirror, before its move to `geotab_demo_fh4` with
> `bronze`/`silver`/`gold` schemas — the figures stand, only the location moved).
